## 현재 상태

- PR1 [#23](https://github.com/sysysysyb/AMUQ/pull/23)과 PR2 [#24](https://github.com/sysysysyb/AMUQ/pull/24) 병합 완료. PR2의 실제 병합 결과는 `a6df135`이며 작업별 19개 커밋을 보존했음.
- PR3는 `feat/8-add-auth-ui`에서 인증 화면과 공용 UI를 작업별로 구성했음. 기존 구현 및 검토 기록과 새 이관 결과는 [인증 화면 기록](issue-8/03-auth-web.md)에 보존함. 아직 원격에 게시하지 않음.
- PR3에서 가입의 JSON이 아닌 429 응답도 서버의 재시도 시각을 반영하도록 수정했음. 수정 전 회귀 4개 실패를 확인했으며 최종 묶음 검증 결과는 기록에서 구분함.
- 사용자는 이번 PR3 재구성에 한해 전체 로컬 커밋 뒤 묶어서 검사하도록 승인했음. 과거 검토와 새 검토의 실제 범위를 구분하고 원격 게시와 병합은 별도 승인을 받음.
- 승인된 네 PR의 범위와 순서를 유지하며 PR4 Docker preview는 아직 착수하지 않음.

## 원본 브랜치의 전체 CE 리뷰

- **완료 범위:** 최초 152파일의 13관점 검토 후, `10ba8df`부터 `184b066`까지의 179파일로 범위를 확장하고 Docker와 토스트의 5관점 검토를 추가했음. 최종 보고서와 후속 수정의 독립 재검토까지 완료했음
- **지적과 처리:** 최신 전체 CE의 P2 2건과 P3 1건에 따라 가입 인증 만료 후 초점과 안내, 토스트 테스트의 시간 제어, 화면 이탈 뒤 늦은 Google 응답 처리 수정했음. 승인 상태를 잘못 적은 과거 P2 1건은 `2468de6`에서 해결했음
- **검증:** 원본의 후속 수정에서 일반 172개 통과, DB 전용 130개 생략. 가입 코드 분리 전과 후의 개발 E2E 각각 77개, 웹 단위 22개, 타입과 린트, Docker API/Next 빌드, HTTPS E2E 80개 통과했음
- **한계:** 외부 모델 실행은 보고 전용 권한을 보장하지 못해 진행하지 않음. Claude의 독립 반론 검토로 보완했으며 외부 모델의 검증 성공으로 기록하지 않음
- **후속 확인:** 각 PR을 구성한 실제 변경은 별도로 검증하고 독립 검토해야 함. 원본 전체 CE 결과만으로 중간 PR의 검증을 대신하지 않음

## 다음 순서와 남은 조건

1. PR3의 작업별 로컬 커밋과 묶음 검사 결과를 사용자에게 보고함.
2. 별도 원격 게시 승인을 받은 뒤 인증 화면 PR을 생성함. 병합 역시 별도 승인 대상임.
3. PR3 병합 후 기존 순서대로 PR4 Docker HTTPS preview를 준비함.

- DB pool과 요청 중 정리의 성능 및 운영 비용은 **MVP 배포 직전**에 확인함. 사용자 결정에 따라 pool 크기 **1, 5, 10, 20** 등으로 비교하며 아직 측정하지 않음.

- 원본의 JSON이 아닌 429 응답 문제 8-11-04 / P3를 PR3에서 수정했음. 서버의 요청 제한 정책은 유지하며 [화면 기록](issue-8/03-auth-web.md#pr3-이관--작업별-커밋-재구성)에 새 검증 결과를 구분함
- PR2 추가 검토의 EXTRA-04 / P3는 처음에는 보류했으나 사용자 요청으로 공백 제거 후 빈 이메일을 거부하도록 수정했음. [서버 기록](issue-8/02-auth-server.md#extra-04-후속-수정--공백-google-이메일-거부)에 수정 전 실패와 수정 후 통과 보존. 단위 154개, 통합 147개와 HTTP E2E 3개 및 정적 검사와 빌드 통과. 독립 검토에서 코드와 테스트 지적 없었으며 기록 P3 2건의 처리와 최종 재확인 완료
- 기존 계획의 로컬 자료 참조와 U04 결과 저장 위치는 로컬 보관 방침과 맞지 않아 관련 작업 착수 전에 승인받아 정리해야 함. 해당 참고 자료와 U04 결과 저장 위치의 계약은 이번 PR에서 변경하지 않음
- MVP 최초 구현 전 기준 SHA는 Stage 7 전에 Git 이력으로 확인해야 함. 아직 기록하지 않음
- Issue #8의 모든 관련 PR 병합, Issue 종료와 공개 증거 보존을 확인하기 전에는 로컬 리뷰 자료를 삭제하지 않음
