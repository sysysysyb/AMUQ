## 28-2. E2E Suite Split

- PR: [#34](https://github.com/sysysysyb/AMUQ/pull/34). 승인 커밋 `b28709acd10636b38e1126b00bd49f1986ff0d16`과 리베이스 병합 커밋 `0f5d57742240a2e62382cb003f1639ea126754eb`의 파일 내용 일치 확인.
- PR 시작 SHA: `e21dc4c6b11d1978b9ed85e222361a63618b7974`.
- **Codex**: E2E 84개를 사용자 흐름 기준으로 3개 파일에서 13개로 재배치. 인증 화면은 로그인, Google 인증과 계정 연결, 재설정, 가입 양식, 공통 입력과 화면 동작을 구분. 실제 API 요청을 검증하는 `http-foundation.spec.ts`의 3개 보존.
- `signup-ownership.spec.ts`에는 이메일 확인, 재발송과 가입 요청 재시도, `signup-completion.spec.ts`에는 인증 뒤 비밀번호 전송, 만료 후 재인증과 완료 흐름을 배치. 각 파일의 시간과 모의 API 설정은 동일한 준비 함수를 통해 적용.
