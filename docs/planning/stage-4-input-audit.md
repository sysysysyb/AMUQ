# Stage 4 계획 입력 감사

## 결론

`/ce-plan`을 막는 미해결 충돌은 없다. 상위 요구사항이 하위 선행 문서의 오래된 범위를 명시적으로 대체하므로, 구현 계획은 아래 우선순위와 해소 규칙을 적용해야 한다.

## 감사한 입력과 우선순위

1. `docs/plans/2026-09-09-0037-feat-amuq-mvp-requirements-plan.md`
2. 승인된 Figma와 `docs/DESIGN.md`
3. `docs/STRATEGY.md`
4. `docs/planning/project-handoff.md`
5. `docs/planning/question-schema-and-data-model-v1.md`와 `docs/contracts/generic-question-package.schema.json`
6. `docs/PRODUCT.md`, `AGENTS.md`와 현재 저장소 관례

현재 GitHub Issue와 구현 준비가 끝난 통합 계획은 없다. `docs/solutions/`와 애플리케이션 코드, 패키지 매니페스트, 테스트 설정도 아직 없다.

## 우선순위로 해소된 차이

| 주제               | 하위 문서의 이전 가정                         | Stage 4에서 적용할 계약                                                                                                                                  |
| ------------------ | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 데모 정체성과 수명 | Mammo 공용 데모, 1일 이내의 미확정 TTL        | R4, F6, AE10에 따라 변경 불가능한 AMUQ 기준본에서 방문자별 편집 가능한 임시 사본을 만들고 12시간 후 삭제한다.                                            |
| 데모의 AI 기능     | 제한된 실제 PDF·AI 체험                       | R4와 범위 제외에 따라 데모에서는 PDF 업로드와 AI 생성을 제공하지 않는다.                                                                                 |
| 문제은행 보관      | 문제은행 보관·복원                            | R8-R9에 따라 유지 또는 영구 삭제만 제공한다. 문항의 내부 `archived` 상태는 R29의 과거 기록 보존용이며 사용자 복원 기능이 아니다.                         |
| 문제 입력 방식     | 수동 작성, JSON 가져오기, Mammo seed 이전     | R10과 범위 제외에 따라 사용자 입력은 PDF만 제공한다. 범용 JSON Schema는 AI 구조 검증에 재사용할 수 있지만 수동·JSON 가져오기 UI나 API는 계획하지 않는다. |
| 생성 흐름 단계 수  | 요구사항의 6단계와 디자인의 12개 화면         | `docs/DESIGN.md`가 12개 화면을 R12의 6개 사용자 단계를 세분한 것으로 명시하므로 충돌이 아니다.                                                           |
| 기존 Mammo 자산    | Mammo 앱 코드와 806문항 이전을 전제로 한 일정 | 현재 저장소에는 해당 앱 코드가 없다. Mammo는 디자인·행동 참고 자료이며, 별도 승인 없이 마이그레이션 작업을 계획하지 않는다.                              |

`docs/STRATEGY.md`의 `Mammo 데모` 표현과 `docs/planning/project-handoff.md`의 관련 범위는 현재 AMUQ 요구사항 이전의 기록으로 취급한다. 승인된 요구사항이나 디자인 문서 자체는 이번 감사에서 수정하지 않았다.

## 일치하는 핵심 계약

- Next.js 프론트엔드와 Vercel, Node.js API와 PostgreSQL 및 Railway, 동일 출처 `/api` 프록시는 현재 기술 기준선으로 서로 일치한다.
- 사용자 소유권은 검증된 서버 세션에서 파생하며 클라이언트 사용자 ID를 신뢰하지 않는다.
- AI 결과는 서버 구조·의미 검증과 사용자 확정 전까지 학습 가능한 revision이 될 수 없다.
- 시험 세션과 응시는 제출 당시 question revision에 연결되고, 이후 수정·삭제가 과거 점수를 바꾸지 않는다.
- 미응답은 별도 상태로 보존하되 점수에서는 오답으로 계산한다.
- 원본과 내용 포함 중간 산출물은 확정 후 삭제하며 실패를 추적하고 재처리할 수 있어야 한다.
- 반응형 페이지당 문항 수, 문제은행 테마, 생성·검토 흐름은 요구사항과 디자인 계약이 일치한다.

## `/ce-plan`에서 결정할 항목

- 저장소·패키지 구조, API 프레임워크, ORM과 마이그레이션 도구
- 비공개 객체 저장소, 백그라운드 작업, 트랜잭션 이메일 제공자
- OpenAI 모델과 한국어·영어 텍스트·스캔 PDF 품질 평가 기준
- PDF 용량·페이지·생성 문항 한도와 20·50·100페이지 평가 방식
- 중단 작업 보관 기간, 삭제 상태와 재시도 정책
- 중복 후보 유사도 기준과 문제당 비교 후보 수
- 차트 라이브러리, 배포 관측과 운영 검증 방식

차트 툴팁은 Figma 오버레이가 없지만 `docs/DESIGN.md`에 동작·접근성 계약이 있으므로 계획 진행을 막지 않는다. 정확한 시각 값은 구현 전에 승인된 Figma 노드에서 측정한다.

## 검증 결과

- R1-R45, F1-F6, AE1-AE10이 빠짐없이 연속적으로 존재한다.
- 범용 Question Package JSON Schema가 Draft 2020-12 문서로 파싱된다.
- 모든 로컬 계획 입력이 존재한다.
- `docs/solutions/`와 애플리케이션·테스트 기반은 아직 없음을 확인했다.

## 4-2 진입 조건

`/ce-plan`은 기존 R-ID를 보존하고 구현 단위에 안정적인 U-ID를 추가한다. 위에서 해소된 하위 가정을 다시 질문하거나 활성 범위로 되살리지 않고, 남은 기술 결정을 근거와 검증 방법까지 포함해 구현 준비가 된 통합 계획으로 작성한다.
